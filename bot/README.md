# FreeSkyVPN — Telegram-бот

MVP-клиент (фаза 3). Тонкий слой поверх API головы: своей БД и своего
состояния у бота нет, любое решение — какой сервер, жив ли конфиг, что даёт
оплата — принимает голова. Благодаря этому Android-приложение из фазы 5
получит ровно то же поведение, ничего не переписывая.

## Запуск

```bash
python3 -m venv .venv && .venv/bin/pip install -e ".[dev]"
cp .env.example .env   # заполнить TELEGRAM_BOT_TOKEN и HEAD_SERVICE_TOKEN
.venv/bin/python -m botapp.main
```

`HEAD_SERVICE_TOKEN` должен совпадать с `HEAD_SECRET_KEY` на голове — этим
токеном бот аутентифицируется в API (см. `head/app/api/auth.py`).

## Тесты

```bash
.venv/bin/pytest
```

## Что умеет

Три кнопки, без выбора страны:

- **🔌 Подключиться** — `POST /api/v1/connect`, возвращает `vless://`
- **🛠 Не работает** — `POST /api/v1/report-failure`; ниже порога переезжает
  только нажавший, на пороге голова объявляет inbound мёртвым для всех
- **⭐ Подписка** — статус, 7-дневный триал, покупка через Telegram Payments

`/start` — это и есть регистрация: телеграм-аккаунт превращается в
`auth_identities`-запись при том же `user_id`, к которому потом привяжется
телефон или Android (сценарии из §05 чертежа).

## Outbox-воркер

`botapp/outbox.py` фоново разбирает `GET /api/v1/pushes/pending`. Когда
голова объявляет inbound заблокированным, она переселяет всех, кто на нём
сидел, и ставит по строке на каждого — воркер превращает их в сообщения,
чтобы пользователь узнал об обновлении из уведомления, а не обнаружив, что
VPN отвалился.

Подтверждение (`ack`) — по одной строке и только после того, как Telegram
принял сообщение: падение посреди рассылки приводит к повторной доставке, а
не к молчаливой потере. Строка, которую доставить нельзя в принципе
(пользователь заблокировал бота), подтверждается с записанной ошибкой —
иначе она навсегда заклинила бы очередь.

## Чего здесь нет

- **Rewarded video** — в Telegram нет нативного механизма; появится в
  Android-фазе с настоящим SDK. Городить суррогат в боте не стали.
- **Ограничение скорости free-тарифа** — фаза 4, реализуется в Xray-конфиге
  на ноде, а не в клиенте.
