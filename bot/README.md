# FreeSkyVPN — Telegram-бот

**Пульт оператора, не продукт.** Продукт — Android-приложение; бот нужен
затем, чтобы одобрять обновления Xray, выдавать доступ руками для тестов и
привязывать аккаунты. Всем, кого нет в списке операторов, он отвечает
отказом (`botapp/access_control.py`).

Своей БД и своего состояния у бота нет: какой сервер выдать, жив ли конфиг,
есть ли у пользователя оплаченное время — решает голова.

## Запуск

```bash
python3 -m venv .venv && .venv/bin/pip install -e ".[dev]"
cp .env.example .env   # TELEGRAM_BOT_TOKEN, HEAD_ADMIN_TOKEN, TELEGRAM_ADMIN_CHAT_ID
.venv/bin/python -m botapp.main
```

`HEAD_ADMIN_TOKEN` должен совпадать с `ADMIN_API_TOKEN` на голове — им бот
аутентифицируется в служебной части API (заголовок `X-Admin-Token`, см.
`head/app/api/auth.py`). Это **не** тот токен, что вкомпилирован в
приложение: тот открывает только пользовательские маршруты.

Без `TELEGRAM_ADMIN_CHAT_ID` (или `TELEGRAM_ALLOWED_CHAT_IDS`) бот запустится,
но не ответит никому, включая вас. Пустой список значит «никого» намеренно:
бот, отвечающий всем из-за незаполненного конфига, — это отказ, который
замечают по счёту за трафик.

## Тесты

```bash
.venv/bin/pytest
```

## Что умеет

Три кнопки, без выбора страны:

- **🔌 Подключиться** — `POST /api/v1/connect`, возвращает `vless://`.
  Оплаченного времени нет — голова отвечает 402: время даёт реклама в
  приложении, показать её в боте нельзя.
- **🛠 Не работает** — `POST /api/v1/report-failure`; ниже порога переезжает
  только нажавший, на пороге голова объявляет inbound мёртвым для всех
- **🔑 Доступ** — выдаёт время себе без рекламы. Ради этой кнопки бот и
  закрыт списком: она обходит то, чем оплачиваются серверы.

Плюс подтверждение обновлений Xray («⬆️ Обновить» / «✋ Не сейчас»), которое
приходит само, когда голова замечает новую версию.

`/start` — это и есть регистрация оператора: телеграм-аккаунт превращается в
`auth_identities`-запись. `/link <код>` привязывает этот аккаунт к устройству,
которое уже зарегистрировано приложением, — оба оказываются одним `user_id`.

Платная подписка через Telegram Payments была убрана: сервис живёт на
рекламе. Когда она вернётся, её место здесь.

## Outbox-воркер

`botapp/outbox.py` фоново разбирает `GET /api/v1/pushes/pending`. Когда
голова объявляет inbound заблокированным, она переселяет всех, кто на нём
сидел, и ставит по строке на каждого — воркер превращает их в сообщения,
чтобы пользователь узнал об обновлении из уведомления, а не обнаружив, что
VPN отвалился.

Подтверждение (`ack`) — по одной строке и только после того, как Telegram
принял сообщение: падение посреди рассылки приводит к повторной доставке, а
не к молчаливой потере. Строка, которую доставить нельзя в принципе
(пользователь заблокировал бота), подтверждается с записанной ошибкой —
иначе она навсегда заклинила бы очередь.

## Чего здесь нет

- **Rewarded video** — в Telegram нет нативного механизма; появится в
  Android-фазе с настоящим SDK. Городить суррогат в боте не стали.
- **Ограничение скорости free-тарифа** — фаза 4, реализуется в Xray-конфиге
  на ноде, а не в клиенте.
