# От нуля до приложения в эмуляторе

Что делает это руководство: поднимает весь стек на сервере (база, голова,
бот), подключает ноду и запускает Android-приложение в эмуляторе Android
Studio так, чтобы весь путь пользователя проходился целиком.

`DEPLOY.md` — подробный ручной путь и справочник по каждому шагу. Здесь
короткий путь через `install.sh` плюс всё, что касается Android.

## Что понадобится заранее

| Что | Зачем | Без этого |
|---|---|---|
| Сервер Ubuntu/Debian, доступ root | голова, бот, база | ничего не заработает |
| **Заграничный сервер под ноду**, SSH с паролем | сам VPN-трафик | приложение скажет «нет свободных серверов» |
| Токен бота от @BotFather | бот | `install.sh` не пойдёт дальше |
| Свой Telegram id от @userinfobot | бот отвечает только операторам | бот промолчит даже вам |
| ПК с Android Studio | сборка и эмулятор | — |

Нода нужна с самого начала. Голова без неё поднимется и админка откроется,
но выдать конфиг будет неоткуда: `/me/connect` вернёт 503, а приложение
покажет «Сейчас нет свободных серверов».

# Часть 1. Сервер

## 1. Ключ для репозитория

Приватный репозиторий не нужно делать публичным «на минутку» — боты
сканируют GitHub именно в расчёте на такие окна. Дайте серверу ключ только
на чтение.

```bash
ssh-keygen -t ed25519 -C "freeskyvpn-server" -f ~/.ssh/freeskyvpn -N ""
cat ~/.ssh/freeskyvpn.pub
```

Вывод — в GitHub: репозиторий → **Settings** → **Deploy keys** → **Add deploy
key**. **Allow write access оставьте снятой.**

```bash
cat >> ~/.ssh/config <<'EOF'
Host github-freeskyvpn
    HostName github.com
    User git
    IdentityFile ~/.ssh/freeskyvpn
    IdentitiesOnly yes
EOF
chmod 600 ~/.ssh/config

ssh -T git@github-freeskyvpn      # ждём "Hi ...! You've successfully authenticated"
git clone github-freeskyvpn:<владелец>/<репозиторий>.git freeskyvpn
cd freeskyvpn
```

`IdentitiesOnly yes` здесь не для красоты: без него ssh переберёт все
остальные ключи, GitHub оборвёт соединение после нескольких попыток, и вы
получите «Permission denied» при полностью верном ключе.

## 2. Бот и ваш id

**Токен:** напишите @BotFather → `/newbot` → имя → username, оканчивающийся
на `bot`. Скопируйте строку вида `1234567890:AAH...` целиком.

**Свой id:** напишите @userinfobot, он ответит числом.

**Сразу напишите своему боту `/start`.** Telegram не разрешает боту писать
первым, и без этого шага он не сможет прислать вам ни одного уведомления —
установщик об этом предупредит, но исправить сможете только вы.

## 3. Установка

```bash
sudo ./install.sh
```

Скрипт спросит ровно три вещи и всё остальное сделает сам:

| Вопрос | Что отвечать |
|---|---|
| Токен Telegram-бота | строка от @BotFather; проверяется через Telegram сразу |
| Ваш Telegram id | число от @userinfobot; Enter — пропустить |
| Домен для админки | Enter, если домена пока нет |

Восемь шагов, которые он проходит:

1. **Система** — проверяет дистрибутив, ставит `curl` и `python3`.
2. **Docker** — ставит с get.docker.com, если его нет, и запускает демон.
3. **Настройки** — генерирует `POSTGRES_PASSWORD`, `HEAD_SECRET_KEY`,
   `SECRETS_KEY`, `ADMIN_API_TOKEN` и пишет `.env`. Существующий `.env`
   спросит, оставить ли; оставленному допишет недостающие ключи.
4. **Сертификат головы** — `secrets/head_client_cert.pem`. Каждая нода будет
   доверять именно ему.
5. **Сборка и запуск** — `docker compose up -d --build`, 3–5 минут.
   Миграции применяются сами при старте головы.
6. **Готовность** — ждёт `/health` до двух минут, показывает состояние всех
   трёх контейнеров.
7. **Администратор** — создаёт пользователя `admin` и печатает пароль.
8. **HTTPS** — если домен задан, запускает `setup_https.sh`.

В конце — smoke-тест: здоровье, оба токена, что токен приложения не
открывает служебных маршрутов, регистрация и выдача конфига.

Скрипт безопасно перезапускать: неудачный прогон можно продолжить, а не
начинать заново.

## 4. Что сохранить прямо сейчас

- **Пароль админки** — печатается один раз.
- **`.env`** целиком, особенно три ключа.
- **Папку `secrets/`**.

`SECRETS_KEY` шифрует SSH-учётки нод в базе: потеряете — на ноды придётся
заходить руками. `secrets/head_client_key.pem` — то, чему доверяют ноды:
потеряете — переустанавливать весь флот.

## 5. Вход в админку

С доменом — `https://вашдомен/admin`.

Без домена голова слушает только `127.0.0.1:8000` и наружу намеренно не
торчит: админка принимает пароль, по чистому HTTP его перехватят. Со своего
компьютера:

```bash
ssh -L 8000:127.0.0.1:8000 root@<ip сервера>
```

Затем в браузере `http://127.0.0.1:8000/admin`, логин `admin`.

## 6. Первая нода

Админка → **Ноды** → форма:

| Поле | Что вписать |
|---|---|
| IP или хост | адрес заграничного сервера |
| Страна | метка для вас, пользователям не видна |
| Канал ноды | Мбит/с |
| Ёмкость | сколько пользователей держит |
| SSH-пользователь / порт / пароль | доступ от хостера |

Занимает 1–3 минуты: проверка SSH, установка ключа головы, bootstrap
(Docker, Xray, marzban-node), настройка `tc`, пиннинг сертификата ноды.
**В конце пароль на ноде меняется на случайный** — введённый перестаёт
работать, это нормально.

Нода должна быть чистой Ubuntu/Debian с открытым 22-м портом и разрешённым
входом root по паролю (`PermitRootLogin yes`, `PasswordAuthentication yes`
в `sshd_config`).

## 7. Проверка бота

Напишите боту `/start`. Должно появиться меню из трёх кнопок:
**🔌 Подключиться**, **🛠 Не работает**, **🔑 Доступ**.

Бот служебный и отвечает только операторам. Список — это
`TELEGRAM_ADMIN_CHAT_ID` плюс `TELEGRAM_ALLOWED_CHAT_IDS` (через запятую).
Пусто значит «никому», намеренно: бот, отвечающий всем из-за незаполненного
конфига, — это отказ, который замечают по счёту за трафик.

Если бот молчит именно вам — вашего id нет в списке:

```bash
grep TELEGRAM .env
# дописать и перезапустить
docker compose up -d
```

Кнопка **🔑 Доступ** выдаёт время без рекламы — ради неё бот и закрыт
списком. Ею же удобно проверять, что связка «голова ↔ бот» жива.

## 8. Смените пароль админки

Если пароль где-то засветился (скриншот, переписка):

```bash
docker compose exec head python -m app.cli create-admin admin
```

Та же команда — и способ восстановления, если пароль забыт.

# Часть 2. Android Studio и эмулятор

## 1. Проект уже есть — создавать не надо

**Не нажимайте New Project.** Полный Gradle-проект лежит в `android/`.
`New Project` создаст рядом пустой скелет, и вы получите два конфликтующих
проекта.

**File → Open** и выберите папку `FreeSkyVPN/android` — именно её, не корень
репозитория. В корне нет `settings.gradle.kts`, Studio его как проект не
распознает.

## 2. Что поставить

- **Android Studio** — последняя стабильная. JDK внутри неё уже есть.
- **SDK Manager → SDK Platforms**: Android 15 (**API 35**) — проект собирается
  под `compileSdk = 35`.
- **SDK Manager → SDK Tools**: Android SDK Build-Tools, Platform-Tools,
  **Android Emulator**. **NDK** — только если будете собирать tun2socks.

## 3. Куда приложение будет ходить

Создайте `android/local.properties` (в git не попадёт) и допишите к тому,
что там сгенерирует Studio:

```properties
headApiUrl=https://ваш-домен
headServiceToken=<HEAD_SECRET_KEY из .env на сервере>
```

Только `HEAD_SECRET_KEY`. **`ADMIN_API_TOKEN` сюда класть нельзя** — он
выдаёт доступ и перезапускает ноды, а APK скачивает кто угодно.

Три рабочих варианта адреса:

**А. Домена ещё нет — SSH-туннель до сервера.** Проще всего для первой
проверки. На ПК:

```bash
ssh -L 8000:127.0.0.1:8000 root@<ip сервера>
```

```properties
headApiUrl=http://10.0.2.2:8000
```

`10.0.2.2` — это адрес вашего ПК изнутри эмулятора. Он попадёт на
проброшенный порт, а тот — на голову. Отладочная сборка чистый HTTP к
приватным адресам разрешает (`ApiEndpoints.normalise` пропускает только
`10/8`, `172.16/12`, `192.168/16` и localhost, остальное режет).

**Б. Домен с HTTPS есть.** `headApiUrl=https://ваш-домен` — самый близкий к
реальности вариант.

**В. Голова прямо на ПК.** `docker compose up -d` локально, дальше как в
варианте А.

Адресов можно перечислить несколько через запятую — клиент идёт по списку,
пока кто-то не ответит, и запоминает сработавший.

Без этих двух строк проект соберётся, Gradle напечатает предупреждение в
рамке, а приложение получит 401 на каждый запрос.

## 4. Нативные библиотеки

Три вещи не тянутся из Maven. В репозитории их нет намеренно — вес и
лицензии свои.

```bash
cd android && ./fetch-libs.sh
```

Скрипт скачает с GitHub:

- **`libXray.aar`** — ядро Xray (MPL-2.0). Взято не у v2rayNG: та под
  GPL-3.0 и обязала бы открыть исходники приложения.
- **`geoip.dat` / `geosite.dat`** — базы, без которых правило `geoip:ru`
  не находит ничего и часть российского трафика уходит в туннель.

**Третью придётся собрать самому** — готовых `.so` в релизах нет:

```bash
git clone --recursive https://github.com/heiher/hev-socks5-tunnel
cd hev-socks5-tunnel
ndk-build -C android          # нужен NDK, путь в ANDROID_NDK_HOME
```

Разложить по `android/app/src/main/jniLibs/<abi>/libhev-socks5-tunnel.so`.
**Для эмулятора нужен именно `x86_64`** — проверьте, что он есть среди
собранных. Для телефона — `arm64-v8a`.

Эта библиотека превращает пакеты с tun-устройства в потоки для SOCKS: у
Xray нет tun-инбаунда.

## 5. Виртуальное устройство

**Device Manager → Create Virtual Device**:

- **Device:** Pixel 7 (любой современный)
- **System image:** **API 35**, ABI **x86_64**, вариант **Google APIs**
- RAM оставьте по умолчанию

`minSdk = 26`, так что подойдёт и API 26+, но берите 35 — под неё собрано.
Образ **Google Play** тоже годится; для VpnService root не нужен.

## 6. Сборка и запуск

Дождитесь Gradle Sync. Версии Android-библиотек в
`android/gradle/libs.versions.toml` проставлены без возможности проверить
(среда, где писался проект, до `dl.google.com` не дотягивается) — если sync
ругнётся на версию, поднимите её там же, от точной цифры ничего не зависит.

Быстрая проверка среды, без нативных библиотек:

```bash
./gradlew :core:test          # 87 тестов, чистый Kotlin
./gradlew :app:assembleDebug
```

Затем **Run ▶** с выбранным эмулятором. Сборка — **debug**, это важно: в ней
подключена заглушка рекламы, которая всегда отвечает успехом.

## 7. Что в эмуляторе заработает, а что нет

| Что проверяем | Работает | Нужно |
|---|---|---|
| Регистрация устройства, экран аккаунта | да | голова доступна |
| Выбор длительности (15 мин / 1 ч / 2 ч) | да | — |
| Просмотр «рекламы», счётчик «2 из 2» | да | debug-сборка |
| Начисление времени, обратный отсчёт | да | голова |
| Автоотключение по нулю | да | голова |
| Повторное включение без рекламы | да | голова |
| Получение `vless://` от головы | да | **подключённая нода** |
| Экран раздельного туннелирования | да | — |
| **Сам туннель (трафик пойдёт)** | **нет** | `libXray.aar` + `.so` под x86_64 |

Без нативных библиотек всё доходит до момента запуска туннеля, а дальше
приложение честно пишет **«не удалось запустить ядро — обновите
приложение»** (нет `libXray.aar`) или **«не удалось подключить туннель»**
(нет `.so`). Оно не падает — это специально: обе библиотеки за
интерфейсами, чтобы сборка без них оставалась запускаемой.

Реклама в debug-сборке — `DebugAds`: полторы секунды задержки и всегда
успех. В релизной стоит `NoAds`, которая честно говорит «нет рекламы», и
тогда доступ идёт по запасному пути с пониженным приоритетом. Подменить на
`BrokenAds` в `FreeSkyApp.kt`, чтобы специально проверить поведение при
недоступной рекламной сети.

## 8. Что пройти по шагам

1. Первый запуск → приложение само регистрируется. В админке, раздел
   пользователей, появится новая анонимная запись.
2. **Подключиться** → всплывает выбор из трёх пакетов.
3. Выберите **2 часа** — потребует два ролика подряд, увидите счётчик.
4. После второго система покажет **системный диалог согласия на VPN** — это
   `VpnService.prepare()`, так и должно быть, один раз.
5. Смотрите на обратный отсчёт. В админке у пользователя видно то же время.
6. Выключите VPN вручную → включите снова: **рекламы быть не должно**, время
   уже оплачено.
7. Дождитесь нуля (берите пакет на 15 минут) → **VPN выключается сам**, а
   следующее включение снова просит ролик.
8. Экран настроек → список приложений для раздельного туннелирования.
   В свежем эмуляторе приложений мало — поставьте пару APK, если хотите
   увидеть список наполненным.

## 9. Логи

```bash
adb logcat -s FreeSkyVpnService:* XrayRuntime:* Tun2Socks:* DebugAds:*
```

Со стороны сервера:

```bash
docker compose logs -f head
```

## 10. Частые ошибки

**401 на каждый запрос.** `headServiceToken` не совпадает с
`HEAD_SECRET_KEY` на сервере, либо в `local.properties` его нет. После
правки — **Sync Project**, значение попадает в `BuildConfig` на этапе
сборки.

**«Нет связи с сервером».** Эмулятор не дотянулся до головы. При варианте А
проверьте, что SSH-туннель жив, и что адрес именно `10.0.2.2`, а не
`localhost` — внутри эмулятора `localhost` это сам эмулятор.

**«Сейчас нет свободных серверов».** 503 от головы: активной ноды нет.
Добавьте ноду в админке.

**«Время закончилось».** 402 — это штатно, посмотрите ролик.

**Cleartext HTTP blocked.** Собрана релизная сборка вместо debug. В release
чистый HTTP запрещён полностью.

**Уведомление о работе VPN не появляется.** Разрешение
`POST_NOTIFICATIONS` объявлено в манифесте, но в рантайме не
запрашивается — на Android 13+ его нужно выдать руками: Settings → Apps →
FreeSkyVPN → Notifications. Туннель при этом работает.

**Gradle не находит `com.android.application`.** Нет доступа к
`dl.google.com` или не установлен SDK API 35.

## Про телефон вместо эмулятора

Если нужен именно живой туннель, проще не эмулятор: соберите
`libhev-socks5-tunnel.so` под `arm64-v8a` (обычная сборка `ndk-build`),
включите на телефоне отладку по USB и запустите на нём. Остальное —
идентично.
